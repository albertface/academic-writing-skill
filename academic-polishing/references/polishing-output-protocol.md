# Polishing Output Protocol

Use this reference to choose how to present academic polishing results.

## Ask Only When Necessary

Proceed without asking if the user provides text and requests polishing. Infer a standard academic polish.

Ask a brief question only when:

- the target journal, style, or field is essential and cannot be inferred;
- the user asks for a tracked-changes style output but the format is unclear;
- the text is too long for a single response and section order matters;
- substantive claims appear contradictory and revision would require choosing one.

## Standard Output

For most requests, use this structure:

1. Polished text.
2. Key changes.
3. Notes or unresolved issues, if any.

Keep notes short. Do not explain every grammar correction.

## Edit Depth Labels

State the assumed edit depth only when it helps the user evaluate the revision.

- Light polish: grammar, punctuation, and fluency.
- Standard polish: clarity, concision, cohesion, and academic tone.
- Deep revision: organization, paragraph logic, and argument flow.

## Bilingual Academic Users

If the user writes in Chinese and provides English academic text, respond in Chinese unless they ask otherwise. Keep the polished academic text in English.

Useful Chinese labels:

- 润色版本
- 主要修改
- 仍需确认
- 结构建议

## Preserve Meaning

Before finalizing, compare the polished version against the original for:

- unchanged claim strength;
- unchanged scope and population;
- unchanged method and result relationships;
- unchanged numerical values and citations;
- no added causal language unless causal evidence exists;
- no lost limitations or caveats.

## High-Risk Academic Content

For abstracts, conclusions, grant claims, and reviewer responses, be especially conservative with:

- novelty claims;
- causal claims;
- statistical significance;
- limitations;
- policy or clinical recommendations;
- statements about prior literature.

If the text overclaims, soften it and briefly note why.
